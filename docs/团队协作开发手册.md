# 智训通 · 团队协作开发手册（极简版）

> 本手册面向**非专业开发背景的同事**（如产品经理），只需照着步骤操作，不需要理解 Git 原理。
> 适用成员：dengyan（管理端）、yangjingui（移动 H5）

---

## 0. 一句话说明

项目代码放在 **GitHub** 上（`github.com/tang3110718311/newzhixuntong`），大家把代码"下载到电脑、改好、传回去"。GitHub 会自动记录谁改了哪里。

## 1. 分工与分支（先看清楚你是哪个）

| 你是谁 | 管哪个模块 | 用哪个分支 | 改哪些文件 |
|--------|-----------|-----------|-----------|
| dengyan | 管理端（后台网页） | `feat-admin` | `apps/admin/` 下的文件 |
| yangjingui | 移动 H5（手机端） | `feat-mobile` | 移动端相关文件 |

> **铁律**：你只在自己的分支上工作，**绝不要去动别人的分支和 `main` 分支**。

## 2. 首次准备（只做一次）

### 2.1 装工具
1. 安装 **Node.js**（版本 22 或以上）：https://nodejs.org
2. 安装 **Git**：https://git-scm.com（一直点"下一步"装完即可）

### 2.2 把代码下载到电脑
打开命令行（Windows 按 `Win + R`，输入 `cmd` 回车），执行：

```bash
# 1. 进入你想放代码的目录，例如 D 盘
cd D:\

# 2. 下载项目（把【你的分支】换成上面的分支名，如 feat-admin）
git clone -b 你的分支 https://github.com/tang3110718311/newzhixuntong.git zxt-next
cd zxt-next

# 3. 安装依赖（第一次会比较久，等它跑完）
npm install

# 4. 初始化数据库
npm run setup
```

> 如果下载时提示要账号密码，找你同事要 GitHub 账号权限，或用配好的 SSH。

### 2.3 配置环境变量（重要）
项目根目录有一个 `.env.example` 文件，把它**复制一份**，命名为 `.env`（注意文件名就叫 `.env`，不要带后缀）。里面的内容保持默认即可，第一次不用改。

## 3. 日常开发流程（每天重复）

### 3.1 开始一天：先同步最新代码
```bash
git pull
```
> 作用：把其他人（或宏哥）刚提交的代码更新到你电脑上。**每天开始前一定要做**。

### 3.2 启动项目看效果
开两个命令行窗口：

```bash
# 窗口1：启动后台服务（API）
npm run dev:api

# 窗口2：启动前端页面（admin 或 h5）
npm run dev:admin
```

然后在浏览器打开：
- 管理端：`http://localhost:3000`

> 启动后浏览器会自己重新加载（热更新），你改代码保存后，网页会自动刷新，不用手动重启。

### 3.3 改代码
用编辑器（推荐 VS Code）打开项目，改你负责的文件。改完**保存**。

### 3.4 提交改动（把成果传回 GitHub）
```bash
# 1. 查看改了什么（确认没有改错文件）
git status

# 2. 把改动加入待提交
git add .

# 3. 提交（写一句这次改了什么，用中文即可）
git commit -m "完成了XX功能"

# 4. 推送到 GitHub（传回去）
git push
```

> **提交信息写清楚**，例如"登录页改成和原型一致"、"新增资料库上传功能"，这样宏哥 review 时一看就懂。

---

## 4. 完成一个功能后：发起合并请求（PR）

你的代码改好后，需要让宏哥审核后才能合入主分支。

1. 打开浏览器访问：`https://github.com/tang3110718311/newzhixuntong`
2. 页面顶部会出现你分支的提示，点击 **"Compare & pull request"**
3. 填一个标题（如"管理端登录页改版"）+ 简单描述
4. 点击 **"Create pull request"** 提交

> 然后等宏哥审核通过后合并。期间如果宏哥提了修改意见，改完再 `git push` 即可，PR 会自动更新。

## 5. 常见问题（遇到先看这里）

### ❓ 推不上去，提示 "rejected"（被拒绝）
说明远程代码比你新。执行：
```bash
git pull
```
再重新 `git add .` → `git commit` → `git push`。

### ❓ 不知道当前在哪个分支
```bash
git branch
```
当前分支名前面会有 `*` 号。

### ❓ 想看看今天改了哪些文件
```bash
git status
```

### ❓ 改坏了想放弃当前文件的修改
```bash
git checkout -- 文件名
```
（注意：这会丢掉这个文件的修改，确认不要了再用）

### ❓ 端口被占用，启动失败
说明已经有程序在跑，或者上次没关干净。执行：
```bash
npm run stop:local
```
再重新启动。

## 6. 验收标准（提交前自检）

1. ✅ 我改的代码在浏览器里能正常看到效果
2. ✅ `npm run typecheck` 不报错（执行后没有红色错误）
3. ✅ 我只改了属于自己的文件（`git status` 检查）
4. ✅ 提交信息写清楚了
5. ✅ 已经 `git push` 推送到 GitHub

---

## 7. 遇到搞不定的问题

- 不要慌，先截图报错信息
- 找宏哥或团队里懂技术的人帮忙
- 不要擅自 `git push --force`（会覆盖别人的代码，很危险）

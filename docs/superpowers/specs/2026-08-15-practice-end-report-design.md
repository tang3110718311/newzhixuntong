# 对练结束、阶段性报告与正式完成设计规格

- 日期：2026-08-15
- 作者：小唐（星辰超级智能体）
- 关联工程：zxt-next（apps/mobile、apps/api、packages/database）

## 一、目标与范围

将对练结束流程从当前单一的“完成/放弃”改为可区分的三类结果：放弃、阶段性报告、正式报告。确保用户主动结束时行为稳定，阶段性报告不会被统计为正式完成，正式完成只能在达到最低回答次数且 AI 认可目标达成时产生。

本次范围包括：

- 后端会话结束判定和报告生成状态；
- 数据库会话、训练记录的报告类型及结束原因；
- 移动端主动结束入口和报告页跳转；
- 任务/场景完成次数只统计正式报告；
- 相关纯函数、接口路径、类型检查和构建验证。

本次不包括：

- AI SSE 流式架构改造；
- 重新设计评分模型或提示词体系；
- 修改无关的启动脚本、协作文件和部署基础设施。

## 二、业务规则

以本次会话的有效学员回答次数 `roundCount` 为准：

| 条件 | 会话结果 | 报告 | 是否计正式完成 |
|---|---|---|---|
| `roundCount < 3`，用户主动结束 | `abandoned` | 无 | 否 |
| `roundCount >= 3`，用户主动结束但未达成目标 | `completed` | 阶段性报告 | 否 |
| `roundCount >= 3`，连续三次跑题等自动结束 | `completed` | 阶段性报告 | 否 |
| `roundCount >= 4` 且 AI 认可目标达成 | `completed` | 正式报告 | 是 |
| 达到最大轮次但未达成目标 | `completed` | 阶段性报告 | 否 |

“正式完成”必须同时满足：至少 4 次有效学员回答，以及 AI 的目标达成判断。任何其他结束原因即使会话状态为 `completed`，也只能生成阶段性报告。

## 三、数据模型

### 3.1 AiTrainingSession

新增或补充以下字段：

- `reportType`：`none`、`progress`、`final`；默认 `none`；
- `endReason`：`user_end`、`target_achieved`、`off_topic`、`max_round`；
- `targetAchieved`：布尔值，表示本次会话是否被判定为目标达成。

现有 `roundCount` 继续表示有效学员回答次数，不新增不可信的前端次数作为完成依据。

### 3.2 TrainingRecord

新增或补充：

- `reportType`：`progress` 或 `final`；
- `endReason`：与会话保持一致。

阶段性报告复用现有评分结果、逐轮评分和报告查询接口；任务完成统计必须过滤 `reportType = final`。

SQLite 初始化和兼容迁移均使用现有 `ensureColumn` 机制，旧数据默认按既有正式完成记录处理，避免历史记录被全部改写。

## 四、后端流程

### 4.1 用户主动结束

`/api/ai/chat` 的 `action=end`：

1. 校验会话仍为 `in_progress`；
2. 读取会话 `roundCount`；
3. 少于 3 次：写入 `abandoned`、`endReason=user_end`、`reportType=none`，不生成记录；
4. 达到 3 次：写入 `completed`、`endReason=user_end`、`reportType=progress`，异步调用现有评分保存函数；
5. 返回 `isFinished=true`、会话 ID、报告类型和报告生成状态，供移动端进入报告页或等待轮询。

### 4.2 AI 自动结束

保留现有 AI 结束标记、连续跑题和最大轮次判断，但统一转换为结束原因：

- AI 认可目标达成：`target_achieved`；
- 连续三次跑题：`off_topic`；
- 达到最大轮次：`max_round`。

只有 `roundCount >= 4` 且结束原因是 `target_achieved` 时，报告类型为 `final`；其他自动结束均为 `progress`。

### 4.3 报告与完成统计

- 阶段性报告和正式报告均写入 `TrainingRecord`，以便用户查看；
- 报告详情和按会话轮询继续复用现有接口；
- 场景/任务完成次数、完成进度和正式训练次数只统计 `reportType = final`；
- 评分合格线继续按场景 `passScore`，不在本次改为统一固定分数。

## 五、移动端流程

- 对练页的返回/结束训练入口调用 `action=end`，不再只切换前端视图；
- 返回少于 3 次：关闭当前会话并回到场景页，不进入报告；
- 返回达到 3 次：进入报告页，报告标题明确显示“阶段性报告”；
- 自动完成后根据 `reportType` 显示“阶段性报告”或“正式报告”；
- “再来一次”继续创建新会话；
- 兼容报告生成中的轮询状态和 TTS 播放清理。

## 六、错误处理与兼容

- `action=end` 重复提交时沿用现有已关闭会话错误，不重复生成报告；
- 报告异步生成失败时保留会话状态和结束元数据，允许按会话接口恢复评分；
- 旧会话缺少新增字段时按 `reportType=final` 兼容读取，避免历史报告消失；
- TTS 失败仍按上一轮语音同步方案降级为全文文字并允许重播。

## 七、测试要点

1. 少于 3 次主动结束：会话为 `abandoned`，无训练记录。
2. 3 次主动结束：生成 `progress` 报告，不增加正式完成次数。
3. 4 次以上且目标达成：生成 `final` 报告，增加正式完成次数。
4. 4 次以上但跑题或达到上限：生成 `progress` 报告，不增加正式完成次数。
5. 重复结束请求不会重复评分或重复创建记录。
6. 报告按会话查询、报告轮询和历史详情均能区分报告类型。
7. 现有语音同步测试、移动端类型检查和生产构建继续通过。

## 八、明确的实现边界

- “有效学员回答”沿用现有 `roundCount` 的计数逻辑，不在本次重新定义文本质量评分；
- “AI 认可目标达成”沿用现有 AI 结束标记及结束判定提示，不新增独立模型；
- 本次不处理前端本地 `practiceTimes` 的历史展示语义，只移除其作为完成判定依据的可能性；
- 不提交或部署工作区中与本设计无关的启动脚本和协作配置改动。

# 智训通商用化整改路线

> 目标：从“能演示”升级到“客户可试用、可部署、可持续迭代”。  
> 原则：先清假数据和假按钮，再打通核心闭环，最后做安全、部署和可运维。

## 一、商用红线

1. 不展示假数据：没有真实数据时必须显示空状态、配置引导或创建入口。
2. 不保留假按钮：按钮点击后必须执行真实动作、跳转到真实页面，或明确提示未配置原因。
3. 不把本地状态当服务端事实：学习进度、考试成绩、训练完成状态最终要以后端数据为准。
4. 不在仓库明文保存密码、Token、服务器口令、模型 Key。
5. 不让前端绕过 API 访问数据库、文件系统或模型能力。

## 二、P0：先消除客户一眼能发现的问题

- 清理移动端示例考试、示例考试记录、示例成绩等假数据。
- 排查所有 `showToast` 伪动作、`alert` 假导出、无 `href` 的假链接。
- 每个核心按钮建立真实行为：刷新、导出、查看、开始、提交、删除、发布。
- 所有空列表提供真实空状态：暂无数据、请管理员发布、请先创建题库等。
- 对登录、验证码、任务详情、对练、考试、报告页做一轮手工验收。

## 三、P1：打通第一条可卖闭环

推荐优先闭环：

```text
管理员创建题库 -> 添加题目 -> 创建考试 -> 发布考试
-> 学员端看到考试 -> 开始答题 -> 提交答案 -> 生成成绩
-> 管理端统计/能力画像读取真实成绩
```

验收标准：

- 管理端创建的数据能在移动端看到。
- 学员端提交后，成绩进入后端 `exam_attempts / exam_answers`。
- 能力画像、数据看板、考试列表都读取同一份真实成绩。
- 刷新页面后数据不丢。
- 无考试时不展示任何示例考试。

## 四、P2：把训练闭环做实

```text
资料学习 -> AI 对练 -> STT/TTS -> 训练记录 -> AI 评分 -> 复盘报告 -> 申诉
```

重点：

- 资料完成状态入库，不只存 localStorage。
- 场景考试记录入库，不只存 localStorage。
- 对练报告可从任务详情、能力画像、训练记录入口进入。
- AI 未配置时给出清晰错误，不生成假回答。
- 评分模型未配置时，区分“规则评分兜底”和“AI 评分不可用”。

## 五、P3：安全与部署

- 移除仓库里的明文服务器密码、默认口令兜底和敏感测试脚本。
- 生产环境禁止 `ALLOW_DEV_TENANT_HEADER`。
- 统一 Cookie / Bearer Token 策略，逐步减少 localStorage Token 依赖。
- 建立部署环境 `.env.example` 和检查脚本。
- AI Provider Key 必须加密保存，前端永远不可见。

## 六、P4：技术债收敛

- 同步 `schema.prisma`、`sqlite/init.mjs`、`sqlite.ts` 三套表结构。
- 把 `admin-dashboard.tsx` 按业务模块继续拆分，避免 4000+ 行主组件继续膨胀。
- 抽公共 API client，减少各组件重复读取 `zxt-admin-auth`。
- 补最小自动化冒烟测试：登录、任务列表、考试创建、考试提交、训练记录详情。
- 开启真实 lint，不再依赖 `--no-lint` 构建。

## 七、每次开发的沟通模板

你可以直接这样提需求：

```text
按商用化路线做 P0/P1。
这次只做：某个页面/某个按钮/某条闭环。
验收标准：我点击 X，应该看到 Y，并且刷新后数据还在。
```

我会默认按以下顺序执行：

1. 先判断是否有假数据、假按钮、假成功提示。
2. 再查前端事件、API、数据库落库三段是否接通。
3. 小步修复，不大范围重构。
4. 跑类型检查/构建/必要的接口冒烟。
5. 告诉你“已修什么、还剩什么、下一步最该做什么”。

# 智训通「先问后做」沟通协议（grill-me 中文版）

> 本协议移植自 Matt Pocock 的 grill-me 技能，适配智训通 zxt-next 项目的多 AI 工具协作场景。
> 目标：任何 AI 工具（Codex / 星辰智能体 / WorkBuddy / Trae / Claude Code）在本项目工作时，都按同一套"先拷问、后动手"的沟通方式与宏哥协作。

---

## 一、协议目标

在动手写代码之前，把需求逼清楚。核心信念：

> **"把想法说清楚"这一步本身就是最有价值的。**

---

## 二、核心规则（五条，全部强制）

### 规则 1：反复追问，直到共同理解
- 针对宏哥提出的需求/计划，**逐细节追问**，直到双方形成共同理解。
- 未确认理解一致之前，**不开始任何实质行动**（不写代码、不改文件、不建分支）。

### 规则 2：按决策树逐个问
- 沿着决策树往下走：先确定能独立回答的问题，再问依赖前一个答案的问题。
- **每次只问一个问题**。禁止一次性抛出一堆问题让宏哥不知所措。
- 如果某个问题必须在另一个问题确认后才能回答，等前一个答案确定后再问。

### 规则 3：每个问题给推荐答案
- 每个问题都必须给出**推荐答案/倾向选项**（例如"我建议用 A，因为……，你看行吗？"）。
- 宏哥只需回"同意/用你建议的"即可，不用自己组织语言。
- 若宏哥对某问题没有想法，直接按推荐答案推进。

### 规则 4：能查的事实不占用提问
- 能从项目文件、代码、工具、文档（如 `docs/skills/zxt-prototype-alignment.md`、`MEMORY.md`、`三窗口并行开发分工.md`）查到的事实，**自己去查**，不浪费时间问宏哥。
- 只有**需要宏哥拍板的决策**才停下来等回答。

### 规则 5：确认后再行动
- 双方理解一致前，**不得开始任何实施动作**。
- 对话末尾应给出**完整方案总结**，请宏哥确认；确认后才进入开发/写文件阶段。

## 3、智训通项目专用补充规则（结合项目实际情况）

以下补充规则与 grill-me 原版同等效力，违反任何一条都视为违反协议：

### 3.1 需求来源不同，追问顺序不同
| 需求场景 | 先问什么 | 再问什么 |
|---------|---------|---------|
| 无原型的一句话需求 | 目标/范围 | 形态（页面/接口/脚本）→ 核心功能 → 技术方案 → 数据字段 |
| 有原型截图的页面对齐 | 先复述页面结构与疑问清单（第 1 轮不改代码） | 逐块对齐差异（必须修复/建议修改/仅供参考三级）→ 数据模型与状态流转 → 边界情况 |
| 后端 API / 数据层改动 | 数据结构与字段 | 兼容性（`ensureColumn` 增量？）→ 幂等/并发 → 落盘时机（sql.js 内存库必须先停进程再写库） |

### 3.2 项目铁律（不问，直接遵守）
- 代码**只读/拉取，严禁 push**、不建远程分支/tag/MR（项目只改本地）。
- 严格按 `docs/skills/zxt-prototype-alignment.md` 对齐原型：**正文 14px（禁 13px）**、标题 24px、卡片标题 20px、统计卡数字 24px；间距卡间 16px / 模块 20px / 区块 24px；`home-grid` 两列（中间 + 右侧 278px），右侧 3 卡纯白底；统计卡列数 6 卡 3 列 / 4 卡 4 列 / 3 卡 3 列。
- 筛选区统一 `filter-bar`/`filter-row`/`filter-input`，**禁止内联样式**。
- 页面数据**按原型写死静态数据**（唯一例外：学员首页接真实 API）。
- 对练中心全套规则见 `docs/skills/zxt-prototype-aligning.md` 及 `MEMORY.md` 智训通项目条目。
- 数据库操作：API 用 sql.js（内存库+定期 saveToFile 落盘），**写库必须先停进程 → 写库 → 再启动**，否则会被内存旧数据覆盖；服务用 `next start` 生产模式，代码改动必须 `next build` + 重启才生效。

### 3.3 人机分工
| 职责 | 归属 |
|------|------|
| 事实查证（读文件/搜索/查代码/看文档） | AI，主动做 |
| 需求决策（范围、优先级、技术选型、字段） | 宏哥拍板 |
| 提示词方案、推荐答案、风险评估 | AI 先给推荐 |
| 最终确认 | 宏哥 |

## 4、对话交互模板（示例）

```
宏哥：帮我把对练中心加个导出功能。

小唐（按协议）：
  好的，先确认一件事（每次只问一个）：
  导出功能主要是给「学员端」用还是「管理员端」用？
  - A. 学员端：导出自己的对练记录 PDF（推荐，跟现有"查看报告"一致）
  - B. 管理员端：导出全部学员对练数据 Excel（用于台账）
  你选哪个？
```

等宏哥答完 → 追问下一个依赖问题 → 所有关键问题问完 → 输出完整方案总结 → 确认后动手。

## 5、适用场景与边界

| 场景 | 是否走协议 |
|------|:---:|
| 新功能、需求、方案、新页面 | ✅ 必须走完整流程 |
| 已有原型的页面对齐 | ✅ 按 3.1 第二行流程 |
| 改已有代码的一行/小改动 | ✅ 但可大幅缩短：先问"影响范围/改哪"确认后动手 |
| 明确小事（改个文件名、删临时文件） | ⏭️ 跳过追问，直接做 |
| 宏哥明确说"不用问，直接做" | ⏭️ 跳过追问 |
| 安全类操作（删除、发布、push、改库） | ✅ 必须问，且需确认 |

## 8、协议底线

1. 每次最多问 1 个问题，带推荐。
2. 能从文件查到的事实，不问。
3. 决策必须宏哥拍板，AI 不替决策。
4. 确认理解一致前，不动手。
5. 项目铁律（只读不 push、原型规范、sql.js 写库流程）永不打折。
